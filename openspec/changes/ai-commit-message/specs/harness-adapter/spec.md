# Spec Delta

## Purpose

定义多个 AI CLI 后端在本工具中的统一抽象：调用时必须抑制哪些副作用、各自的传输层如何被解析成
同一种结果、错误如何分类、用户如何选择与回退，以及环境诊断需要回答哪些问题。

## ADDED Requirements

### Requirement: 后端暴露统一接口

每个后端 MUST 向核心暴露相同的能力探测与生成接口。后端 MUST NOT 获得对用户仓库的写入权限，
MUST NOT 决定暂存哪些文件、提交哪些内容，也 MUST NOT 执行提交或推送。更换后端 MUST NOT
改变提交语义。

#### Scenario: 更换后端
- **WHEN** 用户从一个后端切换到另一个后端
- **THEN** 生成的消息格式与提交行为保持一致，只有措辞可能不同

#### Scenario: 后端尝试越权
- **WHEN** 某后端在生成过程中试图修改仓库内容
- **THEN** 该行为被运行环境阻止，且不影响本次提交的内容快照

### Requirement: 抑制后端副作用

只读沙箱不等同于禁用工具。系统 MUST 针对每个后端分别关闭其工具、扩展、技能、提示模板、
上下文文件发现、外部工具协议与会话持久化。系统 MUST NOT 依据单一沙箱参数宣称调用无副作用。

#### Scenario: 后端默认会加载扩展与上下文文件
- **WHEN** 调用一个默认会加载扩展、技能与仓库上下文文件的后端
- **THEN** 这些加载项被逐项关闭，模型只看到系统构造的输入

#### Scenario: 环境启用了外部工具协议
- **WHEN** 用户环境中为该后端配置了外部工具协议服务
- **THEN** 调用时这些服务被显式禁用

### Requirement: 子进程环境隔离

读取原仓库的子进程 MUST 保留必要的 Git 环境。运行后端的子进程 MUST 清除指向原仓库的 Git
环境变量，并在受控的临时工作目录中运行。两类子进程 MUST NOT 共用同一套环境处理逻辑。
所有子进程 MUST 以参数数组方式启动，MUST NOT 通过 shell 字符串拼接执行差异内容、模型输出
或文件名。

#### Scenario: 后端在临时目录中运行
- **WHEN** 系统启动后端子进程
- **THEN** 该进程不继承指向原仓库的 Git 环境变量，其工作目录为受控临时目录

#### Scenario: 路径包含特殊字符
- **WHEN** 本次提交涉及的路径包含空格、中文、换行或 shell 元字符
- **THEN** 这些路径被正确传递，且不发生任何命令执行

### Requirement: 分别解析各后端的传输层

不同后端的标准输出 MUST NOT 被当作同一种格式。系统 MUST 先按各后端的传输层解析出最终结果文本，
再解析候选结构，再由统一校验器校验。非零退出、明确的错误事件、截断的输出、空结果、缺少完成标记
或格式不符 MUST 一律视为失败，MUST NOT 被写入提交信息。

#### Scenario: 后端输出事件流
- **WHEN** 某后端以事件流形式输出进度、推理与最终内容
- **THEN** 系统只提取最终结果，进度与推理内容不进入提交信息

#### Scenario: 事件流被截断
- **WHEN** 后端输出在完成标记之前中断
- **THEN** 系统判定为失败，不写入提交信息

#### Scenario: 后端将输出写入指定文件
- **WHEN** 某后端支持把最终消息写入指定文件
- **THEN** 系统读取该文件，不从日志中拼接结果

### Requirement: 诊断输出不外泄输入内容

后端失败时可能将完整输入（含差异内容）回显到其诊断输出。系统 MUST 捕获并抑制后端的诊断输出，
只向用户呈现分类后的简短错误原因。系统默认 MUST NOT 记录原始差异或后端的完整输出。
临时文件 MUST 使用仅当前用户可访问的权限并及时清理。

#### Scenario: 后端失败并回显输入
- **WHEN** 后端失败且将完整输入回显到诊断通道
- **THEN** 用户只看到一行分类后的失败原因，终端不被差异内容刷屏

### Requirement: Profile 的四个正交维度与选择优先级

后端、供应商、模型与思考强度 MUST 作为四个独立概念表达。思考强度 MUST NOT 被拼接进模型标识。
系统 MUST NOT 假定所有模型支持相同的思考强度取值。Profile 的选择优先级 MUST 为：
命令行参数、环境变量、当前仓库配置、本机默认值。

#### Scenario: 单次切换后端
- **WHEN** 用户通过环境变量指定本次使用的 profile
- **THEN** 该次提交使用指定 profile，仓库配置与本机默认值不被修改

#### Scenario: 仓库级默认
- **WHEN** 仓库配置中设定了 profile 且未提供命令行参数或环境变量
- **THEN** 系统使用仓库配置指定的 profile

### Requirement: 配置的共享边界

仓库共享配置 MUST 只包含提交规范，MUST NOT 携带任何凭证，MUST NOT 允许定义任意 shell 命令。
后端、模型、可执行文件路径与认证方式的选择 MUST 保存在本机配置中。团队成员 MUST 能在同一仓库
使用不同后端而得到一致的消息格式。

#### Scenario: 团队成员使用不同后端
- **WHEN** 两名成员在同一仓库分别配置了不同后端
- **THEN** 两者生成的提交信息遵循同一套格式规范

#### Scenario: 共享配置试图定义命令
- **WHEN** 仓库共享配置中出现可执行命令定义
- **THEN** 该配置被拒绝

### Requirement: 有序回退链

系统 SHALL 支持配置有序的后端回退链。一次生成中 MUST 至多切换一次后端，且切换 MUST 计入总
超时预算。失败原因 MUST 被分类：配置错误 MUST NOT 通过反复尝试其他后端来掩盖。由于切换后端
意味着相同差异可能被发送给另一家服务，回退链 MUST 由用户显式配置。

#### Scenario: 首选后端额度耗尽
- **WHEN** 首选后端因额度耗尽而失败，且用户已配置回退链
- **THEN** 系统切换到链中下一个后端，并在诊断输出中说明发生了切换

#### Scenario: 配置错误
- **WHEN** 首选后端因模型标识无效而失败
- **THEN** 系统报告配置错误，不通过切换后端掩盖该问题

### Requirement: 超时与进程清理

系统 MUST 设定总超时预算，子调用预算 MUST NOT 超过剩余总时间。计时 MUST 使用单调时钟。
达到截止时间时，系统 MUST 取消后端进程及其子进程并清理临时文件。

#### Scenario: 后端超时
- **WHEN** 后端在总超时预算内未返回结果
- **THEN** 系统取消该进程及其子进程、清理临时文件，并按失败路径处理

### Requirement: 环境诊断

系统 SHALL 提供诊断能力，报告各后端的可执行文件路径、版本、能力支持情况、认证状态与当前配置。
诊断默认 MUST NOT 发起模型请求。后端版本缺少所需的限制参数时，诊断 MUST 报告不兼容，
系统 MUST NOT 静默移除这些限制参数继续调用。

#### Scenario: 查看可用后端
- **WHEN** 用户执行诊断
- **THEN** 系统报告每个后端是否可用及不可用的原因，且不消耗模型额度

#### Scenario: 后端版本过旧
- **WHEN** 某后端的版本不支持所需的副作用抑制参数
- **THEN** 诊断报告该后端不兼容，调用时不会降级为无限制调用

### Requirement: 防止嵌套调用

当编码 agent 自身执行提交时，hook 可能再次拉起同种后端。系统 MUST 设置内部重入标记以阻止
递归调用。生成子进程 MUST NOT 提交代码。后端自身禁止嵌套会话时，系统 MUST 返回明确失败或
使用用户预先配置的其他 profile，MUST NOT 清除后端的保护性环境变量。

#### Scenario: 编码 agent 执行提交
- **WHEN** 某编码 agent 在其会话中执行 `git commit`
- **THEN** 系统检测到重入并返回明确结果，不递归拉起同种后端

#### Scenario: agent 已提供消息
- **WHEN** 编码 agent 通过 `-m` 提供了提交信息
- **THEN** 系统不生成消息
