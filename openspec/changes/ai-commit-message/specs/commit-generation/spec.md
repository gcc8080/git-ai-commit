# Spec Delta

## Purpose

定义从提交内容快照到一条可用提交信息之间的全部可观察行为：输入里包含与排除什么、采集过程的确定性、模型看到的内容如何被约束、
输出必须满足的结构与格式，以及证据不足或输出不合规时系统如何表现。

## ADDED Requirements

### Requirement: 输入只包含本次提交的内容

系统 MUST 依据基准与目标两个快照计算差异、文件清单与统计。未暂存的修改与未跟踪文件 MUST NOT 进入模型输入；部分暂存时
MUST 只描述被选中的部分。系统默认 MUST NOT 扫描提交范围以外的仓库内容。

#### Scenario: 存在未跟踪文件
- **WHEN** 工作区存在未跟踪文件，而本次未将其暂存
- **THEN** 该文件不出现在模型输入中，也不出现在生成的消息里

#### Scenario: 部分暂存
- **WHEN** 用户通过 `git add -p` 只暂存了某文件的部分修改
- **THEN** 模型输入只包含被暂存的那些片段

### Requirement: 采集过程确定且不执行外部转换

差异采集 MUST NOT 执行用户或仓库配置的外部 diff 程序与 textconv 转换，其结果 MUST NOT 受差异显示类配置影响。文件路径
MUST 按原始字节处理，MUST NOT 被解释为模式匹配，MUST NOT 因含有空格、换行、非 ASCII 字符或 shell 元字符而被错误拆分或
引发命令执行。该约束同样适用于预热过滤中的差异检查（见预热规格）。

#### Scenario: 配置了 textconv
- **WHEN** 仓库为某类文件配置了 textconv 转换程序
- **THEN** 采集过程不执行该程序，模型输入中不含其转换结果

#### Scenario: 改变差异显示配置
- **WHEN** 用户修改了 `diff.context`、`diff.noprefix` 等显示类配置
- **THEN** 进入模型输入的变化集合不变

#### Scenario: 路径包含特殊字符
- **WHEN** 本次提交涉及的路径包含空格、中文、换行或 shell 元字符
- **THEN** 这些文件被正确识别与描述，且不发生任何命令执行

### Requirement: 秘密内容排除

系统 MUST 在构造模型输入之前，按可配置的清单排除敏感文件的内容（默认涵盖环境变量文件、私钥、证书与密钥库）。文件的新路径
与重命名或复制的源路径中任意一个匹配清单，其内容就 MUST 被排除；被删除文件的旧内容同样适用。被排除的文件 MUST 仍以
"发生了变化"的事实出现在输入中。系统 MUST 向用户明示：基于模式的排除不保证发现全部秘密。

#### Scenario: 修改环境变量文件
- **WHEN** 本次提交修改了 `.env` 或私钥文件
- **THEN** 模型输入中只出现该文件发生变化的事实与统计，不含任何内容行

#### Scenario: 敏感文件被重命名为普通文件名
- **WHEN** 本次提交将 `.env` 重命名为 `notes.txt`
- **THEN** 该文件的内容不进入模型输入

#### Scenario: 删除敏感文件
- **WHEN** 本次提交删除了一个私钥文件
- **THEN** 被删除的旧内容不进入模型输入

### Requirement: 输入预算与省略披露

超出预算的差异 MUST 按文件分配预算，并在输入中显式标注每个文件的覆盖状态（完整、部分省略、仅统计、二进制、内容排除）。
系统 MUST NOT 截断输入后仍声称内容完整。只有被降噪的文件发生变化时，系统 MUST 仍报告该变化。二进制文件、Git LFS 指针与
子模块 MUST 只以变化事实呈现，MUST NOT 提供其内容，系统 MUST NOT 进入子模块读取内容。

#### Scenario: 超出预算的大规模差异
- **WHEN** 本次差异超过配置的输入预算
- **THEN** 输入中按文件标注覆盖状态，被省略的部分被显式列出

#### Scenario: 只有锁文件变化
- **WHEN** 本次提交只修改了依赖锁文件
- **THEN** 系统仍报告该文件发生了变化，不会得出"无内容可描述"的结果

#### Scenario: 子模块更新
- **WHEN** 本次提交更新了子模块指向的提交
- **THEN** 输入只包含子模块从旧提交到新提交的事实

### Requirement: 输入内容一律作为数据

差异中的源代码、注释、文件名、分支名与历史提交消息 MUST 作为待分析的数据呈现给模型，MUST NOT 被当作指令。系统 MUST 在
模型输入中显式声明这一约束。

#### Scenario: 差异中含有指令样式的文本
- **WHEN** 被提交的代码或注释中含有"忽略此前全部指令"之类的文本
- **THEN** 该文本作为普通内容被分析，不改变系统对输出格式与语言的要求

### Requirement: 结构化候选与拒绝结果

后端 MUST 返回符合已发布 schema 的两种结果之一：候选，或拒绝结果。候选至少包含类型、可空的 scope、单行非空的标题、字符串
数组形式的正文，以及非空说明或空值的破坏性变更字段；拒绝结果说明证据不足的原因。系统 MUST 拒绝含有额外字段、控制字符、
尾注格式行的候选，并 MUST 拒绝正文中出现输入里不存在的 issue 编号的候选。`!` 标记与 `BREAKING CHANGE:` 尾注 MUST 由系统
依据破坏性变更字段渲染，MUST NOT 由模型直接产出。

#### Scenario: 合法候选
- **WHEN** 后端返回符合 schema 的候选
- **THEN** 系统校验通过后将其渲染为最终文本，写入消息文件

#### Scenario: 破坏性变更
- **WHEN** 候选的破坏性变更字段为非空说明
- **THEN** 渲染结果中的 `!` 标记与 `BREAKING CHANGE:` 尾注由系统统一生成

#### Scenario: 模型拒绝生成
- **WHEN** 后端返回拒绝结果
- **THEN** 系统按生成失败的条件规则处理，不写入任何内容

#### Scenario: 候选伪造尾注
- **WHEN** 候选正文中包含 `Signed-off-by:` 或 `Co-Authored-By:` 行
- **THEN** 该候选被判定为不合规

#### Scenario: 候选编造 issue 编号
- **WHEN** 候选正文引用了一个在输入中不存在的 issue 编号
- **THEN** 该候选被判定为不合规

### Requirement: 输出解析不修补

对不支持原生结构化输出的后端，系统 MUST 只允许剥去最外层的代码围栏，剥去后 MUST 是完整、合法的结构化数据。截断的输出、
普通文本与不完整的结构 MUST 被判定为失败，MUST NOT 被修补成成功结果。超长内容 MUST 通过至多一次纠正解决，否则判定为失败，
MUST NOT 被裁剪。纠正 MUST 计入同一总时间预算。

#### Scenario: 输出被代码围栏包裹
- **WHEN** 后端输出的合法 JSON 被一层代码围栏包裹
- **THEN** 系统剥去围栏后正常校验

#### Scenario: 输出被截断
- **WHEN** 后端输出的 JSON 在中途截断
- **THEN** 系统判定为失败，不写入消息文件

#### Scenario: 标题超长
- **WHEN** 候选的标题超过长度上限
- **THEN** 系统至多请求一次纠正；纠正后仍超长则判定为失败，不裁剪原文

### Requirement: 语言与 header 长度

系统 MUST 按配置强制提交信息的语言，默认为中文。长度约束 MUST 作用于完整 header（含类型、scope 与破坏性标记前缀）。
系统 MUST 分别校验显示宽度（按 East Asian Width 计算）与字符串长度，两者均有默认上限，且 MUST 允许仓库配置覆盖。

#### Scenario: 中文 header 的显示宽度
- **WHEN** 配置语言为中文，候选 header 的字符数未超限，但显示宽度超过上限
- **THEN** 该候选被判定为超长

#### Scenario: 仓库覆盖默认上限
- **WHEN** 仓库配置指定了自己的长度上限
- **THEN** 系统按仓库配置的值校验

### Requirement: 风格取自历史，语言与格式取自配置

系统 MUST 从仓库历史中推断消息的结构特征（scope 的使用习惯、是否写正文、标题句式），所用的历史样本数量与字节上限 MUST 固定。
历史样本 MUST 只包含提交标题，以及在本地判定的"该提交是否有正文"标记，MUST NOT 包含正文内容。历史提交使用的语言
MUST NOT 覆盖配置指定的语言。第一版 MUST 只输出 conventional 格式，仓库显式配置 MUST 优先于历史推断。

#### Scenario: 英文历史与中文配置
- **WHEN** 仓库历史提交为英文，而配置指定输出中文
- **THEN** 生成的消息沿用历史的结构习惯，描述文字为中文

#### Scenario: 历史未使用类型前缀
- **WHEN** 仓库历史提交大多没有 conventional 类型前缀
- **THEN** 生成的消息仍使用 conventional 格式

#### Scenario: 历史提交带有正文
- **WHEN** 用于推断风格的历史提交中有带正文的提交
- **THEN** 模型输入只包含这些提交的标题与"有正文"标记，不包含正文内容

### Requirement: 证据约束与不编造

系统 MUST 在模型输入中约束：只描述可从差异中确认的变化，不声称测试通过、线上问题已解决或性能已提升等无法从差异证实的结论，
覆盖不完整时不猜测被省略的内容。这是提示层约束；系统只对本地可机械校验的项（结构、禁止的尾注与 issue 编号）作确定性判定。
证据不足时系统 MUST 以拒绝结果转人工，MUST NOT 产出"更新代码"之类的通用占位消息。

#### Scenario: 差异不足以判断意图
- **WHEN** 本次差异无法支撑对变更意图的判断
- **THEN** 系统转人工填写，不产出通用占位消息

### Requirement: 预览不产生提交

系统 SHALL 提供只生成、不提交的预览方式，用于查看当前已暂存内容对应的消息。预览 MUST NOT 创建提交，MUST NOT 修改暂存区。

#### Scenario: 预览当前暂存内容
- **WHEN** 用户请求预览
- **THEN** 系统输出生成的消息，仓库的 HEAD 与暂存区保持不变
