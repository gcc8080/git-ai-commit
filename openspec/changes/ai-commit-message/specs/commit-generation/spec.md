# Spec Delta

## Purpose

定义从提交内容快照到一条可用提交信息之间的全部可观察行为：输入里包含与排除什么、模型看到的内容
如何被约束、输出必须满足的结构与格式，以及在证据不足或内容失效时系统如何表现。

## ADDED Requirements

### Requirement: 输入只包含本次提交的内容

系统 MUST 依据两个不可变的内容快照（基准与目标）计算差异、文件清单与统计。未暂存的修改与
未跟踪文件 MUST NOT 进入模型输入。部分暂存时 MUST 只描述被选中的部分。系统默认 MUST NOT
扫描提交范围之外的仓库内容。

#### Scenario: 存在未跟踪文件
- **WHEN** 工作区存在未跟踪文件而本次未将其暂存
- **THEN** 该文件不出现在模型输入中，也不出现在生成的消息里

#### Scenario: 部分暂存
- **WHEN** 用户通过 `git add -p` 只暂存了某文件的部分修改
- **THEN** 模型输入只包含被暂存的那些片段

### Requirement: 秘密内容排除

系统 MUST 在构造模型输入之前，按可配置的清单排除敏感文件的内容（默认涵盖环境变量文件、
私钥、证书与密钥库）。被排除的文件 MUST 仍以"发生了变化"的事实出现在输入中，但不得提供其内容。
系统 MUST 向用户明示：正则式脱敏不保证发现全部秘密。

#### Scenario: 提交包含环境变量文件
- **WHEN** 本次提交修改了 `.env` 或私钥文件
- **THEN** 模型输入中只出现该文件发生变化的事实与统计，不含其任何内容行

### Requirement: 输入预算与省略披露

大规模差异 MUST 按文件分配预算，并在输入中显式标注每个文件的覆盖状态（完整、部分省略、
仅统计、二进制、内容排除）。系统 MUST NOT 截断输入后仍声称内容完整。仅有被降噪文件发生变化时，
系统 MUST 仍报告该变化事实。字节预算 MUST NOT 被当作精确的 token 预算。

#### Scenario: 超出预算的大规模差异
- **WHEN** 本次差异超过配置的输入预算
- **THEN** 输入中按文件标注覆盖状态，被省略的部分被显式列出

#### Scenario: 只有锁文件变化
- **WHEN** 本次提交只修改了依赖锁文件
- **THEN** 系统仍报告该文件发生了变化，不产生"无内容可描述"的结果

#### Scenario: 二进制文件变化
- **WHEN** 本次提交包含二进制文件的增删改
- **THEN** 输入提供变化事实与统计，不提供其内容

### Requirement: 输入内容一律作为数据而非指令

差异中的源代码、注释、文件名、分支名与历史提交消息 MUST 作为待分析的数据呈现给模型，
MUST NOT 被当作可执行的指令。系统 MUST 在模型输入中显式声明这一约束。

#### Scenario: 差异中含有指令样式的文本
- **WHEN** 被提交的代码或注释中含有形如"忽略此前全部指令"的文本
- **THEN** 该文本作为普通内容被分析，不改变系统对输出格式与语言的要求

### Requirement: 结构化候选输出

模型 MUST 返回符合已发布 schema 的结构化候选，字段至少包含类型、可空的 scope、单行非空的标题、
字符串数组形式的正文，以及非空说明或空值的破坏性变更字段。系统 MUST 拒绝含有额外字段的输出。
最终的 `!` 标记与 `BREAKING CHANGE:` 尾注 MUST 由系统依据该字段渲染，MUST NOT 由模型直接产出。

#### Scenario: 合法候选
- **WHEN** 后端返回符合 schema 的候选
- **THEN** 系统校验通过后渲染为最终文本并写入消息文件

#### Scenario: 破坏性变更
- **WHEN** 候选的破坏性变更字段为非空说明
- **THEN** 渲染结果中的 `!` 标记与 `BREAKING CHANGE:` 尾注由系统统一生成

#### Scenario: 输出不合规
- **WHEN** 后端返回非法 JSON、含额外字段或标题为空
- **THEN** 系统可在总预算内纠正一次；仍失败则按失败路径转人工或中止，不写入消息文件

### Requirement: 提交信息语言与标题长度

系统 MUST 按配置强制提交信息的正文语言，默认为中文。标题长度 MUST 按显示宽度（East Asian
Width）约束，MUST NOT 仅按码点数或字节数计算。中文场景的默认上限 MUST 同时满足按字符串长度
计数的常见规范检查工具的上限。

#### Scenario: 中文标题长度
- **WHEN** 配置语言为中文且模型返回过长标题
- **THEN** 系统按显示宽度上限处理，结果在终端中不超过一行的可读宽度

#### Scenario: 仓库覆盖默认值
- **WHEN** 仓库配置指定了自己的标题长度上限
- **THEN** 系统采用仓库配置的值

### Requirement: 风格取自历史，语言取自配置

系统 MUST 从仓库的历史提交中推断消息的**结构**特征（是否使用类型前缀、scope 使用习惯、
是否带正文、标题句式）。历史提交所使用的**语言** MUST NOT 覆盖配置指定的语言。

#### Scenario: 英文历史 + 中文配置
- **WHEN** 仓库历史提交为英文，而配置指定输出中文
- **THEN** 生成的消息沿用历史的结构习惯，但描述文字为中文

### Requirement: 证据不足时不编造

系统 MUST 约束模型只描述可从差异中确认的行为变化。模型 MUST NOT 声称测试通过、线上问题已解决
或性能已提升，除非输入中给出了相应证据。证据不足时 MUST 使用中性表述；覆盖不完整时 MUST NOT
猜测被省略的内容。系统 MUST NOT 在全部内容被过滤或证据不足时产出通用的占位消息。

#### Scenario: 差异不足以判断意图
- **WHEN** 本次差异无法支撑对变更意图的判断
- **THEN** 系统转人工填写，不产出诸如"更新代码"之类的通用占位消息

#### Scenario: 模型给出无证据的断言
- **WHEN** 候选中包含"修复了线上崩溃"但输入中无相应证据
- **THEN** 该候选被判定为不合规

### Requirement: 写入前复核内容一致性

在候选生成完成到写入消息文件之间，系统 MUST 复核 HEAD 与有效 index 的快照。快照已变化时
MUST 丢弃该候选，至多重新生成一次；再次变化则 MUST 中止而不写入。

#### Scenario: 生成期间暂存内容改变
- **WHEN** 候选生成期间用户暂存了新的改动
- **THEN** 系统丢弃过时候选，重新生成一次

#### Scenario: 用户在编辑器中停留期间继续暂存
- **WHEN** 用户打开编辑器期间继续暂存改动，且仓库启用了严格一致性检查
- **THEN** 系统在提交检查末端中止本次提交，并且不覆盖用户已编辑的文字

### Requirement: 预览不产生提交

系统 SHALL 提供只生成不提交的预览方式，用于查看当前已暂存内容对应的消息。预览 MUST NOT
创建提交、MUST NOT 修改暂存区。

#### Scenario: 预览当前暂存内容
- **WHEN** 用户请求预览
- **THEN** 系统输出生成的消息，仓库的 HEAD 与暂存区保持不变
