# Spec Delta

## Purpose

定义提前生成与结果复用的可观察行为：什么时候在后台提前生成、缓存条目由什么决定、命中与未命中
分别如何表现，以及预热失效时系统如何退回到同步生成而不改变任何其他行为。

## ADDED Requirements

### Requirement: 暂存内容变化时触发预热

系统 SHALL 在暂存内容发生变化时于后台提前生成候选消息。触发判断 MUST 依据 Git 提供的索引更新
信号，MUST NOT 依赖对用户 shell 的包装。工作区更新而索引未更新的情况 MUST NOT 触发预热。

#### Scenario: 暂存文件
- **WHEN** 用户执行 `git add`
- **THEN** 系统在后台开始生成候选并写入缓存

#### Scenario: 通过图形界面或其他工具暂存
- **WHEN** 用户通过 IDE、终端 UI 或编码 agent 执行暂存
- **THEN** 预热同样被触发，无需用户配置 shell

#### Scenario: 非索引更新的操作
- **WHEN** 发生切换分支、贮藏、刷新状态等不更新索引的操作
- **THEN** 预热不被触发

### Requirement: 预热不阻塞用户操作

预热 MUST 以后台方式执行，MUST NOT 延迟触发它的那条 Git 命令。预热过程中的任何失败
MUST NOT 产生用户可见的错误，MUST NOT 影响该 Git 命令的退出码。

#### Scenario: 暂存大量文件
- **WHEN** 用户执行 `git add` 暂存大量文件，预热随之启动
- **THEN** `git add` 立即返回，不等待生成完成

#### Scenario: 预热失败
- **WHEN** 后台预热因后端不可用而失败
- **THEN** 用户在暂存时看不到任何错误输出，退出码不变

### Requirement: 缓存条目由内容快照与生成参数共同决定

缓存键 MUST 至少由基准快照、目标快照、profile、模型、思考强度，以及提示模板、配置与排除清单的
版本共同构成。缓存键 MUST NOT 依赖差异的文本表示，因为差异文本会随用户的 Git 显示配置而变化。
缓存键也 MUST NOT 仅由分支名或文件清单构成。

#### Scenario: 用户改变差异显示配置
- **WHEN** 用户修改了影响差异文本呈现的 Git 配置，但暂存内容未变
- **THEN** 缓存仍然命中

#### Scenario: 切换 profile
- **WHEN** 用户切换到另一个 profile 后提交相同的暂存内容
- **THEN** 缓存不命中，系统为该 profile 重新生成

#### Scenario: 提示模板升级
- **WHEN** 工具升级后提示模板版本发生变化
- **THEN** 此前的缓存条目不再命中

### Requirement: 预热去重

预热在开始生成之前 MUST 检查目标缓存键是否已存在或正在生成。已存在或正在生成时 MUST 直接
结束，不重复发起请求。

#### Scenario: 索引信号重复触发
- **WHEN** 同一份暂存内容在短时间内多次触发预热
- **THEN** 只有第一次实际发起生成，其余直接结束

### Requirement: 命中缓存时直接使用

提交时缓存命中且内容快照复核通过的，系统 MUST 直接使用缓存中的候选，MUST NOT 重新发起生成。

#### Scenario: 常规提交命中预热结果
- **WHEN** 用户暂存后执行 `git commit`，且暂存内容自预热以来未变
- **THEN** 消息被立即填入，编辑器几乎无等待地打开

### Requirement: 未命中时退回同步生成

缓存未命中时，系统 MUST 在提交流程内同步生成，并在等待期间向用户提供进度提示。使用临时索引的
提交（如自动暂存提交与限定路径提交）因其内容快照与预热时不同而自然不命中，此时 MUST 按同步
路径处理，MUST NOT 使用基于其他快照的缓存条目。

#### Scenario: 未经暂存直接提交
- **WHEN** 用户执行 `git commit -a` 而未预先暂存
- **THEN** 缓存不命中，系统同步生成并在等待期间显示进度提示

#### Scenario: 预热尚未完成
- **WHEN** 用户在预热完成之前执行 `git commit`
- **THEN** 系统同步生成，不等待后台任务

### Requirement: 缓存作用域与清理

缓存 MUST 存放在仓库自身的 Git 目录之下，MUST NOT 跨仓库共享。不同工作树的缓存与锁
MUST 分别存储。卸载时缓存目录 MUST 被移除。

#### Scenario: 多个工作树
- **WHEN** 同一仓库的两个工作树同时使用本工具
- **THEN** 两者的缓存与锁互不干扰

#### Scenario: 卸载
- **WHEN** 用户执行卸载
- **THEN** 缓存目录被移除

### Requirement: 强制刷新

系统 SHALL 提供显式忽略缓存重新生成的方式。

#### Scenario: 对结果不满意
- **WHEN** 用户请求强制刷新
- **THEN** 系统忽略既有缓存条目重新生成，并以新结果覆盖该条目
