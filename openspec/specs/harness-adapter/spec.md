# harness-adapter Specification

## Purpose

定义多个 AI CLI 后端在本工具中的统一契约：调用时必须抑制哪些副作用、会话记录如何处理、各自的传输层如何被解析成同一种结果、
错误如何分类、用户如何选择与回退、时间预算如何计算，以及环境诊断需要回答哪些问题。

## Requirements

### Requirement: 后端遵循统一契约

每个后端 MUST 对核心提供相同的能力探测与生成契约，并返回同一种结果模型。后端 MUST NOT 获得工具权限，调用参数 MUST NOT
包含用户仓库的路径；后端 MUST NOT 决定暂存哪些文件、提交哪些内容，也 MUST NOT 执行提交或推送。更换后端 MUST NOT 改变
提交语义。

#### Scenario: 更换后端
- **WHEN** 用户从一个后端切换到另一个后端
- **THEN** 生成的消息格式与提交行为保持一致，只有措辞可能不同

#### Scenario: 后端进程的调用方式
- **WHEN** 系统启动任意后端
- **THEN** 其调用参数中不含用户仓库路径，工作目录为受控的临时目录

### Requirement: 抑制后端副作用

只读沙箱不等于禁用工具。系统 MUST 针对每个后端及其受支持版本，逐项关闭工具、MCP 等外部工具协议、扩展与插件、生命周期 hook、
上下文文件发现与技能加载。这些限制是对 CLI 的受限调用，系统 MUST NOT 在诊断或文档中将其表述为操作系统级隔离。系统
MUST NOT 为了继续调用而静默移除任何限制参数。

#### Scenario: 后端默认会加载扩展与上下文文件
- **WHEN** 调用一个默认会加载扩展、技能与仓库上下文文件的后端
- **THEN** 这些加载项被逐项关闭，模型只看到系统构造的输入

#### Scenario: 环境配置了外部工具协议服务
- **WHEN** 用户环境为该后端配置了 MCP 服务
- **THEN** 调用时这些服务不被加载

### Requirement: 后端版本的兼容性状态

系统 MUST 把每个后端的已安装版本判定为三种状态之一：兼容（版本在合同测试覆盖的范围内）；未验证（不满足兼容，但探测到全部
必需的限制参数）；不兼容（缺少任一必需的限制参数）。仅凭参数存在 MUST NOT 把版本判定为兼容。不兼容的后端 MUST NOT 被调用。
未验证的后端默认可以调用，但系统 MUST 在每次调用的诊断中注明该状态，并 MUST 允许用户在本机配置中拒绝调用未验证的后端。
因不兼容或被该配置拒绝而无法调用时，MUST NOT 触发回退。

#### Scenario: 后端自动更新到未测试的版本
- **WHEN** 某后端自动更新到合同测试范围之外的版本，且必需的限制参数仍然存在
- **THEN** 系统照常调用该后端，并在诊断中注明其为未验证状态

#### Scenario: 用户拒绝调用未验证的后端
- **WHEN** 用户在本机配置中开启了拒绝未验证后端的选项，而所选后端为未验证状态
- **THEN** 系统不调用该后端，也不回退，按生成失败的条件规则处理

#### Scenario: 缺少必需的限制参数
- **WHEN** 某后端版本缺少任一必需的限制参数
- **THEN** 该后端被判定为不兼容，系统不调用它，调用也不会降级为无限制调用

### Requirement: 会话记录处理

后端支持关闭会话持久化时，系统 MUST 关闭。后端不支持时，系统 MUST 在调用结束后删除本次产生的会话；因中断等原因未能删除时，
系统 MUST 能在诊断中列出本工具残留的会话。

#### Scenario: 后端不支持关闭会话持久化
- **WHEN** 调用一个无法关闭会话持久化的后端，且调用正常结束
- **THEN** 本次产生的会话在调用结束后被删除

#### Scenario: 调用被中断后留下会话
- **WHEN** 此类后端的调用因超时被取消，会话未能删除
- **THEN** 诊断能列出这些残留会话

### Requirement: 子进程环境隔离

读取原仓库的子进程 MUST 保留必要的 Git 环境；运行后端的子进程 MUST 清除指向原仓库的 Git 环境变量。两类子进程 MUST NOT
共用同一套环境处理逻辑。所有子进程 MUST 以参数数组方式启动，MUST NOT 通过 shell 字符串拼接来执行差异内容、模型输出或文件名。

#### Scenario: 后端子进程的环境
- **WHEN** 系统启动后端子进程
- **THEN** 该进程不继承任何指向原仓库的 Git 环境变量

### Requirement: 分别解析各后端的传输层

不同后端的标准输出 MUST NOT 被当作同一种格式。系统 MUST 先按各后端的传输层解析出最终结果，再解析结构化结果，最后由统一的
校验器校验。非零退出、明确的错误事件、截断的输出、空结果、缺少完成标记或格式不符 MUST 一律视为失败，MUST NOT 写入提交信息。

#### Scenario: 后端输出事件流
- **WHEN** 某后端以事件流输出进度、推理与最终内容
- **THEN** 系统只提取最终结果，进度与推理内容不进入提交信息

#### Scenario: 事件流被截断
- **WHEN** 后端输出在完成标记之前中断
- **THEN** 系统判定为失败，不写入提交信息

#### Scenario: 后端把结果写入指定文件
- **WHEN** 某后端支持把最终消息写入指定文件
- **THEN** 系统读取该文件，不从日志中拼接结果

### Requirement: 诊断输出不外泄输入内容

后端失败时可能把完整输入（含差异内容）回显到诊断输出。系统 MUST 捕获并抑制后端的诊断输出，只向用户呈现分类后的简短原因。
系统默认 MUST NOT 记录原始差异或后端的完整输出。临时文件 MUST 只允许当前用户访问，并及时清理。

#### Scenario: 后端失败并回显输入
- **WHEN** 后端失败，并把完整输入回显到诊断通道
- **THEN** 用户只看到一行分类后的失败原因，终端不会被差异内容刷屏

### Requirement: Profile 的四个正交维度与选择优先级

后端、供应商、模型与思考强度 MUST 作为四个独立概念表达。思考强度 MUST NOT 被拼接进模型标识；系统 MUST NOT 假定所有模型都
支持相同的思考强度取值；供应商与模型 MUST 以明确的标识指定，MUST NOT 依赖模糊匹配。Profile 的选择优先级 MUST 依次为：
命令行参数、环境变量、仓库级本机配置、本机默认值。

#### Scenario: 单次切换 profile
- **WHEN** 用户通过环境变量指定本次使用的 profile
- **THEN** 该次提交使用指定的 profile，仓库配置与本机默认值不被修改

#### Scenario: 仓库级默认
- **WHEN** 仓库级本机配置设定了 profile，且未提供命令行参数或环境变量
- **THEN** 系统使用该配置指定的 profile

### Requirement: 配置的共享边界

仓库共享配置 MUST 只包含提交规范。仓库共享配置 MUST NOT 携带凭证、MUST NOT 定义可执行命令、MUST NOT 定义回退链、
MUST NOT 开启预热；出现这些内容时，系统 MUST 拒绝该项。后端、模型、可执行文件路径、认证方式、回退链与预热开关
MUST 保存在本机配置中。团队成员 MUST 能在同一仓库使用不同后端，并得到格式一致的消息。

#### Scenario: 团队成员使用不同后端
- **WHEN** 两名成员在同一仓库分别配置了不同后端
- **THEN** 两者生成的提交信息遵循同一套格式规范

#### Scenario: 共享配置试图定义命令或回退链
- **WHEN** 仓库共享配置中出现可执行命令或回退链定义
- **THEN** 系统拒绝该配置项，并在诊断中说明原因

### Requirement: 回退链默认关闭

默认情况下，系统 MUST 只使用一个选定的 profile，第二个后端的调用次数 MUST 为零。只有当用户在本机显式配置了有序回退链时，
系统才 SHALL 回退，且一次生成中 MUST 至多切换一次。回退资格 MUST 按失败类别决定：额度耗尽、限流、网络错误、服务不可用、
超时与未认证允许回退；参数不兼容、版本不兼容或被本机配置拒绝、模型标识无效等配置错误，纠正后仍不合规的输出，模型的拒绝结果，以及用户取消，
MUST NOT 触发回退。发生回退时，系统 MUST 在诊断中说明。

#### Scenario: 未配置回退链时首选后端失败
- **WHEN** 首选后端因额度耗尽而失败，且用户未配置回退链
- **THEN** 系统不调用任何其他后端，按生成失败的条件规则处理

#### Scenario: 已配置回退链时首选后端额度耗尽
- **WHEN** 首选后端因额度耗尽而失败，且用户已配置回退链
- **THEN** 系统切换到链中下一个后端，并在诊断中说明发生了切换

#### Scenario: 配置错误不触发回退
- **WHEN** 首选后端因模型标识无效而失败
- **THEN** 系统报告配置错误，不切换后端

#### Scenario: 模型拒绝不触发回退
- **WHEN** 首选后端返回拒绝结果
- **THEN** 系统不切换后端

#### Scenario: 用户取消不触发回退
- **WHEN** 用户在生成期间取消
- **THEN** 系统不切换后端

### Requirement: 统一时间预算

一次前台生成 MUST 受单一总时间预算约束，等待同一快照的后台任务、后端调用、格式纠正与回退切换 MUST 共用这一预算，
任何一步 MUST NOT 重置预算。计时 MUST 使用单调时钟。达到截止时间时，系统 MUST 取消后端进程及其子进程，并清理临时文件。

#### Scenario: 纠正与回退累计超时
- **WHEN** 首选后端的输出需要一次纠正，随后又发生了一次回退
- **THEN** 这些步骤的总耗时不超过同一个总预算

#### Scenario: 后端超时
- **WHEN** 后端在剩余预算内未返回结果
- **THEN** 系统取消该进程及其子进程，清理临时文件，按生成失败的条件规则处理

### Requirement: 环境诊断

系统 SHALL 提供诊断能力，报告：实际解析到的运行时可执行文件及其版本；各后端的可执行文件路径、版本、能力支持情况（兼容、
不兼容、未验证）与认证状态；当前生效的配置；回退链中共享同一账户额度的后端；本工具残留的后端会话。诊断默认 MUST NOT
发起模型请求。

#### Scenario: 查看可用后端
- **WHEN** 用户执行诊断
- **THEN** 系统报告每个后端是否可用及原因，且不消耗模型额度

#### Scenario: 运行时不可用
- **WHEN** hook 中记录的运行时路径已失效，例如运行时被升级或移动
- **THEN** 诊断报告该问题，并给出修复方式

#### Scenario: 回退链中的后端共享额度
- **WHEN** 用户配置的回退链中，两个后端使用同一账户的额度
- **THEN** 诊断提示这一回退无法恢复额度耗尽时的可用性

### Requirement: 防止递归调用

系统启动的全部子进程（包括 git 子进程与后端子进程）MUST 带有内部重入标记；hook 检测到该标记时 MUST NOT 发起生成或预热。
生成子进程 MUST NOT 提交代码。后端自身禁止嵌套会话时（例如在编码 agent 的会话中调用同种 CLI），系统 MUST 返回明确的失败，
MUST NOT 清除后端的保护性环境变量。

#### Scenario: 本工具自身的 git 调用
- **WHEN** 系统在生成过程中执行会写入 index 的 git 命令
- **THEN** 该命令触发的 hook 检测到重入标记后立即退出，不发起新的生成

#### Scenario: 编码 agent 执行提交
- **WHEN** 某编码 agent 在其会话中执行不带消息的 `git commit`，而所选后端与该 agent 是同种 CLI
- **THEN** 系统以受限方式调用该后端；若后端拒绝嵌套运行，则按生成失败的条件规则处理

#### Scenario: agent 已提供消息
- **WHEN** 编码 agent 通过 `-m` 提供了提交信息
- **THEN** 系统不生成消息
